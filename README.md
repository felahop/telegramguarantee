# Escrow-бот «Гарант» для P2P-сделок в USDT

Telegram-бот удерживает оплату покупателя и выплачивает её продавцу только после подтверждения
обеих сторон. Архитектура и решения — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

**Что умеет:**
- сделки: мастер, команды `/sell` `/buy` `/deal`, inline-режим, приглашения по ссылке, шаблоны, повтор;
- строгий автомат статусов, двойная запись в ledger с проверками в БД, комиссии;
- оплата и выплаты через **CryptoBot**;
- приём в **BEP-20, ERC-20, TRC-20 и Solana**: каждый платёж подтверждают два независимых источника;
- выплаты в **BEP-20, ERC-20 и TRC-20** через отдельный подписант;
- путь «пришлите hash транзакции», если бот не увидел оплату;
- споры и админка с TOTP, сверка балансов каждые 15 минут с автоостановкой выплат при недостаче.

**Чего пока нет:**
- TON (бот не запустится, если он включён);
- выплаты в Solana;
- отдельные депозитные адреса на каждую сделку;
- автоматическая замена застрявшей EVM-транзакции (RBF).

Документы: [архитектура](docs/ARCHITECTURE.md), [запуск в testnet](docs/TESTNET.md),
[риски перед запуском](docs/RISKS.md). **Не принимайте реальные деньги, пока не закрыты блокирующие
пункты из списка рисков.**

## Запуск для разработки

Нужны Python 3.12, [uv](https://docs.astral.sh/uv/), PostgreSQL 16 и Redis 7.

```bash
uv sync
cp .env.example .env               # BOT_TOKEN, BOT_USERNAME, DATABASE_URL, REDIS_URL, ADMIN_IDS
cp chains.example.yaml chains.yaml # включите нужные сети, укажите депозитные адреса
uv run alembic upgrade head
uv run python -m app.bot           # long polling, без вебхука
```

Фоновые задачи (уведомления, таймеры, CryptoBot, наблюдатели сетей, выплаты, сверка):
`uv run python -m app.worker`. Подписант для ончейн-выплат: `uv run python -m app.signer`
(без `SIGNER_URL` воркер подписывает сам — только для разработки).

Продакшен-режим — вебхук: `docker compose up -d` поднимает `postgres`, `redis`, `migrate`, `web`
(порт 8080, пути `/tg/webhook` и `/cryptopay/<secret>`), `worker` и `signer`. Signer находится
только во внутренней сети без выхода в интернет, ему нужен `SIGNER_API_SECRET` длиной от 32 байт. Нужны `WEBHOOK_BASE_URL`
(публичный HTTPS через reverse proxy) и `TELEGRAM_WEBHOOK_SECRET`.

### CryptoBot (Crypto Pay)

1. Testnet: откройте @CryptoTestnetBot → Crypto Pay → Create App. Mainnet — то же в @CryptoBot.
2. Токен приложения → `CRYPTOBOT_API_TOKEN`, `CRYPTOBOT_TESTNET=true|false`.
3. В настройках приложения **включите Transfers** — без этого выплаты продавцам не пройдут.
4. Webhooks → URL `https://<ваш домен>/cryptopay/<CRYPTOBOT_WEBHOOK_SECRET_PATH>` (случайная строка).
   Подпись каждого запроса проверяется; если вебхук потеряется, воркер найдёт оплату опросом.
   Crypto Pay повторяет неуспешную доставку до 17 раз за 3 дня, а потом **отключает вебхуки** —
   после долгого простоя проверьте, что они снова включены (оплаты всё равно найдёт опрос).
5. Получатель выплаты должен хотя бы раз открыть @CryptoBot (@CryptoTestnetBot) — иначе бот
   попросит его об этом и повторит выплату автоматически.
6. Проверьте текущую комиссию Crypto Pay за приём оплаты: если она удерживается из счёта, она
   учитывается как расход сервиса, а минимальная комиссия сервиса должна её покрывать.

### Админы

1. `ADMIN_IDS` в `.env` — Telegram ID админов (роль выдаётся при старте). Другим ролям:
   `uv run python -m app.cli grant-role <user_id> admin|arbitrator|user`.
2. `SECRETS_ENCRYPTION_KEY` — ключ шифрования TOTP-секретов:
   `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`.
3. Каждый админ один раз отправляет боту `/totp` и добавляет ключ в приложение-аутентификатор.
   Потерян телефон → `uv run python -m app.cli reset-totp <user_id>` и снова `/totp`.
4. `/admin` — панель: споры (досье, решение «покупателю / продавцу / разделить %», комиссия
   удерживается или нет), выплаты на подтверждении и проблемные, неопознанные платежи (привязать к
   сделке или вернуть), балансы ledger и CryptoBot, поиск, блокировка пользователей.
   Каждое денежное действие подтверждается кодом TOTP.

### Ончейн-сети (BEP-20, ERC-20, TRC-20, Solana)

1. В `chains.yaml` у сети поставьте `enabled: true`, `deposit_address` (он же горячий кошелёк выплат)
   и для EVM — `chain_id` (56 BSC, 1 Ethereum; testnet 97 / 11155111). Воркер сверяет его с RPC.
2. `rpc` — основной провайдер, `verify_rpc` — **другой** провайдер. Каждый платёж и каждая выплата
   подтверждаются обоими; конфиг с одинаковыми URL не загрузится.
3. Ключи бесплатных тарифов задаются в `.env` (`TRONGRID_API_KEY` и т. п.), в `chains.yaml` указывается
   только имя переменной (`api_key_env`).
4. Воркер при старте сверяет `decimals` контракта с конфигом: у BSC USDT 18, у остальных сетей 6.
   При расхождении он не запустится.
5. Покупатель видит адрес, точную сумму с меткой (последние цифры) и предупреждения о сети и
   комиссии биржи. Сумма, которая не совпала с меткой, уходит в «Неопознанные» к админу.

**Выплаты (BEP-20, ERC-20, TRC-20).** Подписант хранит ключ горячего кошелька в зашифрованном
keystore и сам строит транзакцию из данных выплаты в БД. Получателя и сумму от воркера он не
принимает. Он проверяет одобрения, лимиты и то, что адрес не наш.

```bash
mkdir -p secrets/keystore
# ключ и пароль вводятся скрыто, в историю shell не попадают; один ключ подходит для BSC, ETH и TRON
uv run python -m app.cli keystore-import secrets/keystore/hot.json
```

В `.env` задайте `SIGNER_KEYSTORE_DIR=secrets/keystore` и `SIGNER_PASSWORD` (в проде — Docker secret).
Лимиты подписанта задают `SIGNER_MAX_PAYOUT_USDT` (на одну транзакцию) и `SIGNER_DAILY_LIMIT_USDT`
(за скользящие сутки). Для TRON — `TRON_FEE_LIMIT_TRX`.

На горячем кошельке нужны USDT и монета для газа (BNB, ETH, TRX). Пополнение газа запишите в ledger,
чтобы учёт расходов сходился:
`uv run python -m app.cli record-funding BNB@bsc <адрес> 0.05 gas-topup-1`.

> ⚠️ Solana: приём работает, выплат пока нет: они стоят в очереди, и сверка об этом сообщает. TON
> выключен целиком. Подписант пока работает внутри воркера; вынести его в отдельный контейнер без
> выхода в интернет (§9.2) — следующий шаг усиления.

### Сверка и операторские команды

Воркер раз в 15 минут сверяет баланс приложения CryptoBot с ledger, проверяет инварианты ledger и
ищет зависшее (очередь выплат, таймеры, уведомления, неопознанные платежи, долгие подтверждения).
Проблемы приходят админам сообщением «Сверка: …» с кнопкой в нужный раздел админки.

- **Недостача** держится больше 5 минут и не объясняется выплатами в полёте → выплаты с кошелька
  останавливаются автоматически. Найдите причину, затем «Балансы» → «Возобновить выплаты» (код TOTP)
  или `uv run python -m app.cli resume-payouts cryptobot`. Если недостача не устранена, следующая
  сверка снова остановит выплаты.
- **Излишек** — обычно пополнение, которое не записали. Любое движение денег мимо бота
  записывается в ledger:
  ```bash
  # пополнили баланс приложения CryptoBot на 50 USDT (ref — любая уникальная метка, повтор не задвоит)
  uv run python -m app.cli record-funding USDT@cryptobot cryptobot 50 topup-2026-11-20
  # вывели заработанные комиссии (команда откажет, если деньги нужны пользователям)
  uv run python -m app.cli record-withdrawal USDT@cryptobot cryptobot 20 payout-owner-11 --note "ноябрь"
  # ручной прогон сверки (код выхода 2 — есть критичные проблемы, удобно для мониторинга)
  uv run python -m app.cli reconcile
  ```
- Остановить выплаты вручную можно в «Балансы» без кода: это всегда безопасно.

### Настройки бота в @BotFather

- `/setinline` — включить inline-режим (подсказка: `[@username] 150 USDT [сеть] описание`).
- `/setinlinefeedback` — 100 %, чтобы бот мог обновлять отправленные inline-карточки.
- `/setcommands`:
  ```
  new - Новая сделка
  sell - Продать: /sell @username 150 USDT trc20 описание
  buy - Купить: /buy @username 150 USDT описание
  menu - Главное меню
  help - Как это работает
  admin - Админ-панель (только для админов)
  ```

## Тесты

```bash
TEST_DATABASE_URL=postgresql+asyncpg://user@localhost:5432/escrow_test uv run pytest
uv run ruff check . && uv run mypy app
```

Тесты интеграции и бота работают на настоящем PostgreSQL: блокировки строк, частичные уникальные
индексы и триггеры — часть денежных гарантий. Бот проверяется сквозными тестами: настоящий
диспетчер aiogram и обработчики, вызовы Telegram API записываются в памяти.
